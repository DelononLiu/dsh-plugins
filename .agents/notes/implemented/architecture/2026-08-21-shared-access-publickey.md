# Agent Note: shared 实例跨实例访问（SSH 公钥式认证）

Status: implemented

## Problem

shared 实例（owner 授权其他用户访问）的跨实例访问路径未定：访问者从自己实例跳转到目标实例，怎么认证、怎么校验授权。

## Decision

**v1 = SSH 公钥式认证**（2026-08 定，用户提议采纳）：

- 每个实例持有**身份密钥对**（私钥留本地不出实例；**v1 每实例一对**，公钥随实例档案分发；每用户密钥 v2）。
- owner 在目标实例配置**授权用户/实例的公钥列表**（authorized_keys 式，静态配置——同 dsh-user 静态配置模式）。
- 访问流程：访问者用私钥签名请求 → 目标实例验证公钥在授权列表 + 授权级别（只读/可访问）→ 放行。
- **不做证书链/CA**（无信任层级），v2 再考虑用户级密钥与完整信任体系。

## Alternatives

- 独立登录（访问者在目标实例开账号）——否决：身份是用户自有的，不该变成目标实例上的账号；免密 + 身份可移植更好。
- 完整跨实例信任链（证书/CA）——否决：复杂度高，v1 authorized_keys 式够用。

## Consequences

- dsh-user 增加密钥对生成/管理 + 公钥验证；目标实例配置 shared 授权公钥列表。
- 访问入口：nav 跳转目标实例地址 → 公钥签名 → 校验授权列表。
- 议题 4/5 定稿。
