# Agent Note: AICoding 方法论吸纳——机械闸门 + 正反两链

Status: implemented

## Problem

用户提供《【正向构建 + 反向排错】AICoding 方法论总纲》，核心主张：靠自觉的流程约束对模型无效，
**闸门必须是机械的**（命令/脚本，输出即判据）；故障发生后的现场**一旦被"顺手修一下"就失去证据
价值**（污染即失证）；正向构建（想法→拷问→规格→实施→发布）与反向排错（故障→判定现场是否被污染
→取证/隔离/证伪）是两条链，各自需要落地载体。

本仓库已有一批离散实践（`dsh-pre-push-checks` 的机械命令、`scripts/verify-kernel-upgrade.sh`、
提交规则、worktree 纪律），但没有把它们表述为"闸门"，也没有反向链（排错时先判污染）的任何载体。
引入方式必须避免"再写一份方法论文档就完事"——文档本身不产生闸门。

## Decision

方法论按四层吸纳，**只吸纳能在本仓库变成命令或流程挂载点的部分**，其余明确列为纯判断项：

- **Layer 1（本 note）**：把方法论固化为决策——三条留用（机械闸门优先、污染即失证、维护自改清单）、
  四条收紧（见下节"收紧"）。
- **Layer 2（改造既有 skill）**：`grilling` 追加本项目**高危问题种子清单**（拷问不再依赖模型自由发挥，
  kernel 双实例/端口矩阵/snapshot/Doc 同步等复发问题必须被问到）；`diagnosing-bugs` 前插
  **Phase 0 污染检查闸门**——现场不干净时禁止进入"构造反馈环"（否则在污染现场上建的红绿环是伪证）。
- **Layer 3（新 skill）**：`.agents/skills/dsh-incident-forensics/` 承载反向链的受污染分支
  （A–F：取证/隔离/证伪/验证/恢复优先/复核），含非破坏性快照命令与七条铁律；`diagnosing-bugs`
  判为受污染时交给它。
- **Layer 4（挂载点）**：正向链的验证阶段不新造流程，而是挂到既有闸门——`dsh-pre-push-checks`
  增加"自改清单与快照"两项；`scripts/verify-skills.sh` 成为 skill 自身的机械闸门（frontmatter、
  命令块语法）；`scripts/verify-kernel-upgrade.sh` 保持为内核升级的专用闸门。

### 收紧（对原方法论的四点修正）

1. **不是所有约束都能做成机械闸门**。分三类表述：**机械闸门**（命令有输出即失败）、
   **结构化约束**（格式/清单，可被 lint 但需人判）、**纯判断**（架构取舍、语义正确性）。
   把纯判断写成"必须"只会训练出走过场的勾选。
2. **正向链缺一个显式验证阶段**。原链止于"实施→发布"，本仓库要求实施与发布之间必须过
   `pnpm typecheck` + `dsh-pre-push-checks`（+ 内核升级时 `verify-kernel-upgrade.sh`）——验证阶段
   是闸门挂载点，不是自觉。
3. **两链不正交，共享"种子/不变量"记忆**。正向链拷问出的高危种子 = 反向链优先怀疑的对象清单；
   一次事故的结论必须回灌种子清单，否则两链各自漂移。
4. **A–F 与 diagnosing-bugs 是同一诊断流程的两个分支**，不并列成两套方法论：干净现场走
   "构造反馈环"（原 six phases），受污染现场走 A–F；判定闸门只有一个（Phase 0）。

## Alternatives

- **只写方法论文档**（新增 docs/methodology.md）：无挂载点，模型读过即忘，与"机械闸门"主张自相矛盾 → 否决。
- **全盘照搬 A–F 为独立顶层流程**：与既有 `diagnosing-bugs` 重复且互相冲突（两套 Phase 编号、
  两套完成判据）→ 否决，改为"一个闸门 + 两个分支"。
- **把七条铁律逐条做成脚本**：多数条目（如"恢复优先于理解"）无法机械判定，硬做只会产出
  永远为绿的假闸门 → 否决，按三类约束降级表述。
- **为正向链建新的验证流程/脚本**：与既有 pre-push / kernel-upgrade 闸门重复 → 否决，改为挂载。

## Consequences

- 排错的入口从"读代码猜原因"变为"先判现场是否可信"；判据是命令（`git status`/`git stash list`/
  产物 mtime vs 进程启动时间/并发写者），不是感觉。
- 受污染现场的取证用**非破坏性快照**：`git stash create` + `git update-ref refs/forensics/<ts>`
  不触碰工作区即可固化现场（含未跟踪文件的 tar 归档），因此"先取证再动手"不再与"别丢现场"冲突。
- 每次排错要求维护**本人改动清单**（本次会话自己改了什么）——这是判断"现象是否是我造成的"的唯一依据，
  也是多 agent/多 worktree 并存（本仓库常态）下的基本卫生。
- skill 自身进入机械闸门管理：`scripts/verify-skills.sh` 校验 frontmatter 与内联命令块语法，
  避免"skill 里的命令早就跑不通"这种静默失效。
- 收尾：正反两链的种子清单是同一份；`grilling` 的种子清单增补后，`dsh-incident-forensics` 的
  A 步骤不再重新发明怀疑顺序。
