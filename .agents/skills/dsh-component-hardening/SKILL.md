# 既有组件加固流程（加固链）

**适用**：组件已存在、功能大致齐、但"各种问题"——修一处碰一处、失败静默、文档对不上、
不知道从哪下手。**目标不是重设计，是产出一份能分批执行、每批可验证可回滚的方案。**

## 何时用哪条链

| 处境 | 走哪条 |
| --- | --- |
| 有新想法，要做新东西 | `grilling` → 规格 → 实施（正向链） |
| 故障正在发生，现场可能已被改过 | 先 `diagnosing-bugs` Phase 0；脏现场转 `dsh-incident-forensics`（反向链） |
| 既有组件毛病多，要系统性做好 | **本 skill（加固链）** |
| 既有组件 + **要加新能力/新概念**（模板、版本、删除、权限这类） | 先 `grilling` 把新语义拷问到唯一判读，再回本 skill 从第 1 步走 |
| 单点小 bug、复现明确 | 直接修 + 回归测试，不必走全流程 |

## 六步（每步都有退出闸门）

### 1 · 目标可判定化（Scope）

把"做好"翻译成**现象级目标**：`操作 X → 现象 Y 消失` 或 `操作 X → 能力 Z 可用`。
同时写死 **Out of Scope**（本次明确不做的事，含历史遗留项的显式处置）。

- 产出：目标清单（编号 · 现象 · 验证方式）+ Out of Scope
- 闸门（三条都要过）：
  1. **每条目标写出验证方式**（一条命令，或一个固定操作 + 预期观察）。写不出的降级为
     "待观察"，**不进批次**——没有判据的目标会变成永远做不完的工作。
  2. **验证方式必须无二义**。目标若引入**新概念或新语义**（新名词、新身份、新生命周期、
     权限、删除/迁移这类），先走 `grilling` 拷问到唯一判读再回来。**加固链不豁免拷问**：
     语义没逼唯一，"验证方式"就是假的——同一句话两个人能判出两个结果，批次表也就建在沙上。
     免拷问的只有一种：目标全是**既有语义的显式化**（把已经存在的行为写清判据）。
  3. 目标之间不得互相矛盾（如"老实例不动"与"统一按新布局发现"）；矛盾处必须先拍板。
- 退出：目标清单经用户确认 + 新语义目标的判读唯一 + 无自相矛盾项。

### 2 · 只读取证（Facts）

**不写代码、不改配置。**把"我以为"换成"实测"。先跑这几组：

```sh
PKG=packages/console         # ← 换成目标组件目录，例：packages/dsh-console

# 规模与职责分布：一个文件/类扛 N 个职责 = 后面每批都会互相碰
wc -l $PKG/src/*.ts | sort -n | tail -5
grep -n "^export class \|^  // ---\|^  private [a-z]*(\|^  async [a-z]*(" $PKG/src/index.ts | head -40

# 真实测试数（文档写的通常过期）
(cd $PKG && pnpm test 2>&1 | tail -6)

# 文档声称 vs 实现的差集（陈旧文档=污染源）
grep -rn "<组件名>" docs/architecture.md AGENTS.md | grep -n "测试\|已实现\|待实现"

# 已知缺陷台账（别重新发现一遍）
sed -n '/^## 9/,$p' docs/architecture.md
ls .agents/notes/proposed/**/*.md 2>/dev/null | xargs grep -ln "<组件名>"
```

再补三类**只能实测**的事实：端点/端口的真实可达性与凭据要求（`curl -s -o /dev/null -w '%{http_code}'`）、
哪些状态是内存态（`grep -n "new Map\|new Set" $PKG/src/index.ts`）、失败是否被吞（`grep -c catch $PKG/src/index.ts`）。

- 产出：**事实台账**（编号 · 事实 · 命令 · 输出 · 影响面）+ **不一致清单**（文档说 A、实测 B）
- 闸门：每条事实都带命令与输出；**文档只当线索**，不一致处单列（不许"文档写了所以是那样"）。
- 退出：目标清单涉及的每个面都有实测事实。

### 3 · 成因归类（Causes）

把事实归到成因类，**每条必须落到 `文件:行号` 或符号**——停在"架构问题"就等于没归因：

| 成因类 | 典型证据 |
| --- | --- |
| 单点结构 | 一个文件/类 2000 行、多职责、角色分支写在 `apply()` 里 |
| 权威源冲突 | 同一状态有多处写入者（注册覆写、UI 覆盖、缓存 TTL 滞后） |
| 静默失败 | `catch` 吞错、无 relay 时空转、错误只进 `console.log` |
| 边界未校验 | 端点无凭据、默认信任、回环假设当安全 |
| 状态不持久 | 内存 `Map` 承载本该持久的数据（重启即丢） |
| 陈旧文档 | 文档数字/路径与实测不符，且已被下游引用 |

- 产出：成因聚类（每类含证据位置）+ 目标 → 成因的映射
- 闸门：目标清单里每条都挂得上至少一个成因；挂不上的回到第 2 步补证。
- 退出：没有"孤证"目标，没有无位置的成因。

### 4 · 分批排序（Batches）

**排序看危险度与依赖，不看页面。**默认序：**安全 → 数据正确性 → 可观测性 → 体验**。

每批写清：批名 · 覆盖的目标编号 · 触及面（文件/模块） · 与其他批的依赖 · 回滚方式 · 验收命令。

- 闸门：**每批必须能独立合入并独立回滚**；有编译或运行时依赖的批**串行**（依赖链见 AGENTS.md）；
  批与批不得共享未合入改动。做不到就是把批切错了。
- 退出：用户按批次表确认范围与顺序（这份表就是"解决方案"本身，实现只是执行）。

### 5 · 实施循环（每批一遍）

顺序固定，不许跳：

1. **先写能红的复现**：写测试/构造场景 → 跑 → **必须红**（记录输出）。一开始就绿 = 它没在测这个 bug。
   `(cd $PKG && pnpm test)` 或 `pnpm vitest run -t '<用例名>'`
2. 修到绿，只动台账里那一条。
3. **顺手切结构**：把该块从这个大文件里切出去（切一次 = 一个提交）。不借这批做无关重构。
4. 全套闸门：
   ```sh
   pnpm typecheck && pnpm -r test
   git diff --check                       # 空白/冲突残留
   bash scripts/verify-skills.sh          # 仅当改了 .agents/skills
   ```
   推送前按 `.agents/skills/dsh-pre-push-checks/SKILL.md` 走完整自检。
5. 同步文档与 Agent Note（同一提交），并把台账该条标为已修。

- 闸门：**无红即无修复**；闸门不过不合入。
- 退出：该批验收命令通过 + 台账条目状态更新 + 未引入新的"待观察"。

### 6 · 收口与回灌（全流程一次）

- 文档同步到**单点权威**（哪个文件说了算，明确写出），消除第 2 步的不一致清单
- 新发现的复发面固化成**脚本或测试**（能机械判定的必须变成命令，别留在提示词里）
- 事故/缺陷结论**回灌** `grilling` 种子清单（同一提交），并补 Out of Scope 里的遗留项处置

- 闸门：不一致清单清空；回灌项**必须带命令**（只写得出一句"要注意 X"的属于纯判断，别伪装成闸门）

## 三条不变式（贯穿六步）

1. **命令 > 记忆 > 文档**：取证先跑命令，文档只当线索。
2. **一个提交一个逻辑单元**，每批可独立合入、独立回滚。
3. **能机械判定的才叫闸门**，其余明写"纯判断"——别把判断力伪装成检查项。

## 反模式（踩过的）

- **上来就重构**：没有台账与验收判据的重构没有终点，且无法回滚。
- **按页面排批次**：页面是症状分布，不是依赖顺序；按页面排会让同一处代码被反复改。
- **测试全绿当成没事**：内部行为测试挡不住结构性问题——要的是"先红后绿"，不是"一直绿"。
- **批里夹带顺手改**：回滚粒度被破坏，出问题无法定位是哪一处引起的。
- **边界没定就写实现**：边界模糊会让后面每一批都返工。
- **拿文档当事实**：陈旧文档会把整棵方案树建在伪基线上（先跑第 2 步）。
